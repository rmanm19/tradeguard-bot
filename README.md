## ⚙️ چطور کار می‌کند (مهم)

GitHub Actions هر جاب را حداکثر ۶ ساعت اجرا می‌کند. این ریپو آن را به یک **زنجیره بی‌پایان** تبدیل می‌کند:

```yaml
concurrency:
  group: tradeguard-bot-v3      # (v2 قفل شد؛ نام گروه عوض شد)
  cancel-in-progress: false
```

GitHub در هر گروه همیشه **یک جاب در حال اجرا + یک جاب در نوبت** نگه می‌دارد.
وقتی جاب ۵ ساعت و ۵۰ دقیقه‌ای تمام می‌شود، جابِ در نوبت **بلافاصله** شروع می‌شود.

```
[جاب ۱: 5h50m]──────────────────────────┐
                                        └─► [جاب ۲: 5h50m]──────► ...
                                            ↑ وقفه واقعی: ۳۰ تا ۹۰ ثانیه
```

**آپ‌تایم واقعی: حدود ۹۹.۴٪** — ماهی ۲ تا ۳ ساعت مجموع وقفه، هر بار کمتر از ۲ دقیقه.

### ⏱ از push تا کد زنده: حدود ۵ دقیقه (نه ۶ ساعت)

مشکل قبلی: چون `cancel-in-progress: false` است، کدِ تازه حق ندارد جاب در حال اجرا را
قطع کند؛ پس یک تغییر کوچک می‌توانست تا **۵ ساعت و ۴۰ دقیقه** روی «کد قدیمی» منتظر بماند.

حالا سه قطعه این انتظار را حذف می‌کنند:

| قطعه | چه می‌کند |
|---|---|
| `run_forever.py` | هر ۴ دقیقه (`RESTART_PROBE_SEC`) فهرست `tradeguard-pro` روی `main` را از API می‌گیرد و **هش blob** فایل‌های زمانِ اجرا (`bot.py`، `run_forever.py`، `db_crypt.py`) را با نسخهٔ محلی مقایسه می‌کند. تفاوت داشت؟ تمیز خارج می‌شود. |
| `bot.yml` | چک‌اوت‌ها با `ref: main` انجام می‌شود؛ پس جابِ در صف با **تازه‌ترین** کد شروع می‌کند، نه عکسِ لحظهٔ صف‌شدن. |
| `concurrency` | جابِ در صف بلافاصله جای جابِ خارج‌شده را می‌گیرد — همان زنجیرهٔ همیشگی. |

چند نکته که عمداً این‌طور کار می‌کند:

- **فقط تغییر کد** ری‌استارت می‌کند. کامیت‌های `[skip ci]` مثل «همگام‌سازی تنظیمات مینی‌اپ»
  (که هر چند دقیقه یک‌بار است) SHA شاخه را جلو می‌برند ولی این فایل‌ها را دست نمی‌زنند.
- **بی‌دلیل ری‌استارت نمی‌شود:** اول هش مقایسه می‌شود (یک درخواست، بدون دانلود)؛ اگر
  فرق داشت، محتوا هم گرفته و مقایسه می‌شود تا اختلاف پایان‌خط (CRLF) باعث حلقه نشود.
- **بدون توکن، خاموش:** اگر `GITHUB_TOKEN` نباشد (مثلاً اجرای محلی) هیچ درخواستی زده
  نمی‌شود؛ یعنی سهمیهٔ ۶۰ درخواست در ساعت هدر نمی‌رود و رفتار قبلی برمی‌گردد.
- **پشتیبان قبل از خروج:** خروج با کد ۰ است، پس مرحلهٔ رمزنگاری و ذخیرهٔ دیتابیس سر جایش
  اجرا می‌شود — ری‌استارت هیچ کاربری را از دست نمی‌دهد. (به همین دلیل هم جاب را
  «کنسل» نمی‌کنیم.)
- **دستی:** دستور `/restart` در ربات (فقط ادمین) فایل `restart.flag` را می‌نویسد و همان
  مسیر را طی می‌کند — مثلاً بعد از عوض‌کردن Secretها. `/stats` هم نشان می‌دهد
  `🧩 کد: <sha>` یعنی کدام نسخه همین حالا زنده است.
- **بدترین حالت:** اگر لحظهٔ خروج هیچ جابی در صف نباشد، `watchdog` (هر ۱۵ دقیقه)
  دوباره روشنش می‌کند.

### دیتابیس گم نمی‌شود
`tradeguard.db` (کاربران، پرداخت‌ها، اشتراک پرو) در پایان هر جاب:
1. با `db_crypt.py` (HMAC-SHA256، فقط کتابخانه استاندارد) رمزنگاری می‌شود
2. به Actions Cache می‌رود
3. اجرای بعدی برمی‌گرداند و رمزگشایی می‌کند

> ریپو عمومی است و کش برای همه قابل دانلود — **برای همین رمزنگاری اجباری است**. کلید در Secret است، نه در کد.

## 🚀 راه‌اندازی (۱۰ دقیقه، یک‌بار)

### ۱) ریپو بساز
1. [github.com/new](https://github.com/new)
2. Repository name: `tradeguard-bot`
3. **Public** ← **باید عمومی باشد** (دقیقه‌های Actions نامحدود فقط برای ریپوی عمومی است)
4. **Create repository**

### ۲) فایل‌ها را آپلود کن
> ⚠️ پوشه `.github` با نقطه شروع می‌شود — ویندوز آن را نشان می‌دهد ولی بعضی مدیرهای فایل مخفی‌اش می‌کنند.

1. در صفحه ریپو: **uploading an existing file**
2. پوشه `tradeguard-pro` و پوشه `.github` را **با هم Drag & Drop** کن
3. پایین صفحه: **Commit changes**

اگر `.github` آپلود نشد (بعضی مرورگرها پوشه مخفی را رد می‌کنند):
- **Add file → Create new file**
- اسم فایل را تایپ کن: `.github/workflows/bot.yml` ← اسلش‌ها خودشان پوشه می‌سازند
- محتوای فایل را کپی کن → Commit

### ۳) Secretها را بگذار
**Settings → Secrets and variables → Actions → New repository secret**

> ⚠️ **در کادر Name فقط حروف انگلیسی، عدد و `_` مجاز است. فاصله، خط تیره و حروف فارسی خطا می‌دهد.**
> کادر Value هر چیزی می‌تواند داشته باشد (فاصله، `:`، ایموجی…).

**Secretها:**

| Name (دقیقاً همین) | Value | لازم؟ |
|---|---|---|
| `BOT_TOKEN` | توکن BotFather: `123456789:AAH...` | ✅ **اجباری — بدون این هیچ‌کاری نمی‌شود** |
| `ADMIN_USER_ID` | آیدی عددی خودت (از `@userinfobot`) | ✅ **برای پنل `/admin` اجباری** — بدون آن پنل و `/price` و `/broadcast` برای همه قفل است |
| `TG_DB_KEY` | رمز قوی دلخواه | اختیاری |
| `MINI_APP_URL` | لینک مینی‌اپ | اختیاری |
| `PUBLIC_CHANNEL_ID` | `@yourchannel` | اختیاری |
| `SUBSCRIPTION_STARS` | `300` | اختیاری |

**درباره `TG_DB_KEY`:** اگر نگذارش، کلید رمزنگاری دیتابیس خودکار از `BOT_TOKEN` مشتق می‌شود.
یعنی **هیچ کار اضافه‌ای لازم نیست** — فقط `BOT_TOKEN` را بگذار و برو.
(اگر بعداً `BOT_TOKEN` را عوض کنی، دیتابیس قبلی خوانده نمی‌شود؛ در آن صورت `TG_DB_KEY` را صریح بگذار.)

#### ❌ خطای `Secret names can only contain alphanumeric characters…`
یعنی در کادر **Name** یک کاراکتر غیرمجاز گذاشتی. شایع‌ترین‌ها:

| اشتباه | چرا خطا می‌دهد |
|---|---|
| `BOT TOKEN` | فاصله |
| `BOT-TOKEN` | خط تیره |
| `BOT_TOKEN = توکن` | کپی کل جدول راهنما به‌جای فقط اسم |
| `bottoken.` | نقطه |
| `توکن_ربات` | حروف فارسی |
| `123TOKEN` | با عدد شروع شده |
| `BOT_TOKEN ` (فاصله آخر) | فاصله |
| توکن را در کادر Name چسباندی | `:` و طول زیاد |

✅ درست: `BOT_TOKEN` — فقط حروف بزرگ انگلیسی و یک آندرلاین.

**Actions → TradeGuard Bot → Run workflow**

▶  اجرای bot.py (تلاش #1)

## 🔀 فاندینگ چند صرافی (ابزار آربیتراژ)

در تب رادار، جدولی از **فاندینگ ۸ ساعتهٔ همان ارز در سه صرافی** (Hyperliquid · OKX · Binance) نمایش داده می‌شود.
آخرین ستون، «اختلاف سالانهٔ فاندینگ» است: `(بیشترین − کمترین) × ۳ × ۳۶۵`.

- عدد مثبت یعنی لانگ‌ها به شورت‌ها می‌پردازند؛ ستون‌ها رنگ‌بندی شده‌اند.
- اگر یک صرافی جواب ندهد، همان خانه «—» می‌ماند — **هیچ عددی حدس زده نمی‌شود**.
- یادداشت خودِ جدول صریح است: اختلاف فاندینگ «سود تضمینی» نیست؛ کارمزد، اسلیپیج و نقدشوندگی را خودت باید بسنجی.

## 🧮 ژورنال تریدر: ریسک، حجم پوزیشن و R واقعی

تب ششم مینی‌اپ («ژورنال») سه کار می‌کند:

| بخش | چه می‌کند |
|---|---|
| **ماشین‌حساب ریسک** | بالانس + درصد ریسک + ورود + حد ضرر + هدف → ریسک دلاری، **حجم پوزیشن**، ارزش پوزیشن، R/R و سود در هدف |
| **ثبت ستاپ** | معامله با یک کلیک ذخیره می‌شود؛ «برد/باخت/سربه‌سر» آن را می‌بندد |
| **آمار** | نرخ برد، **انتظار (R)**، ضریب سود، بهترین/بدترین R و **امتیاز انضباط** (حد ضرر + ریسک ≤۱٪ + R/R ≥۱٫۵) |

سه قاعده‌ای که عمداً رعایت می‌شود:

1. **هیچ داده‌ای به سرور نمی‌رود** — همه‌چیز در `localStorage` همان دستگاه است و با «خروجی JSON» قابل برداشت.
2. **R از قیمت‌های خودت ساخته می‌شود**، نه از سود ادعایی: `R = |هدف − ورود| ÷ |ورود − حد ضرر|` و باخت همیشه `−1R`.
3. **ستاپ بی‌حدضرر یا با هدف در جهت اشتباه ذخیره نمی‌شود** — ژورنال ابزار انضباط است، نه ویترین.

با یک کلیک «کارت آمار» می‌توانی همین آمار را به‌صورت تصویر استوری (PNG) به اشتراک بگذاری —
کارت فقط از اعداد خودت ساخته می‌شود و اگر معاملهٔ بسته‌شده نداشته باشی، ساخته نمی‌شود.

همین محاسبه در چت هم در دسترس است:

```
/rr 1000 1 64000 62500 67500
→ ریسک $10 · حجم 0.00666667 · R/R 1:2.33 · سود در هدف $23.33
```

## 🕳 چیزهای تازه (نسخهٔ «محصول خفن»)

**۱) نقشهٔ لیکوئیدیشن (تخمینی) در مینی‌اپ** — برای ۵ ارز با بیشترین OI، قیمت تقریبی لیکوئید
لانگ/شورت در اهرم‌های ۱۰×، ۲۵× و ۵۰× نشان داده می‌شود. فرمول شفاف است
(`فاصله = ۱ ÷ اهرم − ۰٫۵٪ کارمزد نگهداری`) و روی کارت هم نوشته می‌شود که این یک **تخمین از OI**
است، نه دفتر سفارش صرافی. سمت شلوغ بازار هم از علامت فاندینگ خوانده می‌شود.

**۲) فید دادهٔ عمومی، بدون کلید** — ربات هر ~۱۰ دقیقه دو فایل JSON می‌نویسد و پوش می‌کند:

- `docs/api/radar.json` — فاندینگ (٪ در ۸ ساعت)، APR سالانه، OI میلیون‌دلاری، قیمت + ترس و طمع
- `docs/api/stats.json` — فقط شمارنده‌های تجمیعی (کاربر، عضویت تأییدشده، پرو فعال)

اگر دادهٔ زنده در دسترس نباشد **هیچ فایلی نوشته نمی‌شود**؛ عدد ساختگی ممنوع است. مستندات:
`docs/api/index.html`.

**۳) گزارش قیف شریک — `/biz`** (فقط ادمین) — برای هر شریک: کلیک → استارت → عضویت تأییدشدهٔ کانال →
پرو فعال، با نرخ‌ها. subidها (`p_okx_ab12`) زیر یک شریک جمع می‌شوند. همان پیام صریح می‌گوید که
«KYC/دپوزیت را ربات نمی‌داند» و شِمای postback CRM را می‌دهد — یعنی چیزی که یک بروکر واقعاً
می‌تواند ارزیابی کند، بدون اغراق.

**۴) صفحهٔ B2B** — `docs/business.html` (فارسی/انگلیسی) با اعداد واقعی از `api/stats.json`،
چهار جایگاه همکاری، قیف قابل اندازه‌گیری و «خطوط سرخ» (بدون وعدهٔ سود، با افشای کمیسیون).
لینک‌ها به `api/index.html` برای مستندات فنی.

## 🔐 ورود با گوگل + ژورنال ابری و تحلیل روزانه

هر کاربر می‌تواند حساب گوگلش را وصل کند؛ بعد از تأیید، **۳۰ روز پرمیوم** می‌گیرد و
**ژورنال و تحلیل روزانه‌اش داخل ربات** ذخیره می‌شود — نه روی یک گوشی که با پاک‌کردن
مرورگر برود.

### چرا Device Flow (و نه دکمهٔ «Sign in with Google» داخل مینی‌اپ)

مینی‌اپ یک سایت استاتیک روی GitHub Pages است و بک‌اند ندارد که کد گوگل را با
`client_secret` عوض کند؛ از طرفی `Telegram.WebApp.sendData` فقط برای وبه‌اپی کار
می‌کند که از **دکمهٔ کیبورد** باز شده باشد، نه از دکمهٔ اینلاین (که ما استفاده می‌کنیم).
پس همهٔ کار سمت ربات انجام می‌شود:

```
کاربر: /login
ربات → گوگل: POST oauth2.googleapis.com/device/code   (scope: openid email)
گوگل → ربات: user_code = "ABCD-EFGH"
ربات → کاربر: «به google.com/device برو، این کد را بزن»
کاربر (در مرورگر خودش): وارد حساب گوگل می‌شود و Allow می‌زند
ربات ← گوگل: هر ۵ ثانیه توکن را می‌پرسد → id_token
ربات: پرمیوم فعال + حساب وصل ✅
```

رمز گوگل هیچ‌وقت از ربات عبور نمی‌کند و ربات هیچ دسترسی‌ای به جیمیل، درایو یا
مخاطبین ندارد — اسکوپ فقط `openid email` است.

### راه‌اندازی (یک‌بار، ادمین)

| گام | کار |
|---|---|
| ۱ | [console.cloud.google.com](https://console.cloud.google.com/) → پروژهٔ تازه |
| ۲ | APIs & Services → **OAuth consent screen** → نوع *External* → اسکوپ‌ها: `openid`، `email`، `profile` |
| ۳ | Credentials → **Create credentials** → *OAuth client ID* → نوع **TVs and Limited Input devices** |
| ۴ | در تلگرام: `/google id <CLIENT_ID>` و `/google secret <CLIENT_SECRET>` — یا همان دو مقدار در GitHub Secrets |
| ۵ | `/google test` ← یک تماس **واقعی** با گوگل؛ دقیقاً می‌گوید کلیدها و *نوع کلاینت* درست‌اند یا نه |
| ۶ | اختیاری: `/google days 30` (۰ = فقط نشان تأیید، بدون پاداش) · `/google` = وضعیت |

> Secret را می‌توانی در GitHub Secrets بگذاری (`GOOGLE_CLIENT_ID`،
> `GOOGLE_CLIENT_SECRET`). آن‌ها **اولویت** دارند و ورک‌فلو هر دو را به env ربات
> می‌دهد. اگر در تلگرام بگذاری، ربات همان پیام را پاک می‌کند تا در تاریخچهٔ چت
> نماند؛ ولی بدان که مقدارش در دیتابیس (فایل رمزنگاری‌شده در Actions Cache) هم
> ذخیره می‌شود.

راهنمای گام‌به‌گام با اسکرین‌شات‌های متنی و جدول خطاها: **[GOOGLE_LOGIN_FA.md](GOOGLE_LOGIN_FA.md)**.

- حساب گوگل بدون ایمیلِ تأییدشده رد می‌شود.

### چرا این «قفل» کامل نیست (مهم)

«حسابِ قابل‌انتقال» می‌دهد، نه پرداخت. اگر روزی ژورنال باید واقعاً فروش برود،
قفلِ درست همان چیزی است که از اول بود: **پرداخت Stars** یا **چرخهٔ دعوت ۳ نفره**.
گوگل اینجا لایهٔ راحتی و اعتماد است، نه دیوار پرداخت — و در متن داخل ربات هم
همین‌طور گفته می‌شود، نه بیشتر.

> ژورنال تبِ مینی‌اپ همچنان روی همان دستگاه می‌ماند (بدون بک‌اند). نسخهٔ ابری
> داخل ربات است و همین در خودِ مینی‌اپ هم به کاربر گفته می‌شود.

## 🎨 دیزاین «فضا» (space.css + space.js)

کل ظاهر مینی‌اپ یک لایهٔ طراحی جداگانه دارد که **روی** `styles.css` و `app.css`

| لایه | چیست |
|---|---|
| `docs/space.css` | توکن‌های فضایی، سحابی/شبکهٔ پرسپکتیو، شیشه و تیلت سه‌بعدی کارت‌ها، نوار تب شناور، موشن‌گرافیک |
| `docs/space.js` | ساخت صحنه در DOM، اندیکاتور لغزندهٔ تب، پالس اعداد زنده، پارالاکس و تیلت |

**عمق سه‌بعدی** از سه جای واقعی می‌آید، نه از تصویر: شبکهٔ زمین با پرسپکتیو و
نقطهٔ گریز، هستهٔ هولوگرافیک (سه حلقهٔ چرخان با `preserve-3d`) داخل کارت رادار،
و تیلت کارت‌ها که با موقعیت اشاره‌گر محاسبه می‌شود.

سه اصل که عمداً رعایت شده:

1. **بدون canvas و بدون حلقهٔ `requestAnimationFrame` دائمی** — ستاره‌ها و
   شهاب‌ها عناصر CSS‌اند و فقط `transform`/`opacity` حرکت می‌کنند؛ وقتی تب
   مخفی است مرورگر خودش متوقف می‌کند (باتری موبایل).
2. **`prefers-reduced-motion`** همهٔ حرکت‌ها را خاموش می‌کند ولی ساختار و خوانایی
   می‌ماند؛ حالت روشن تلگرام (`tg-light`) هم پالت روشن خودش را دارد.
3. **بدون منبع بیرونی** — هیچ فونت/تصویر/CDN؛ مینی‌اپ آفلاین هم همان شکل است.

تست‌ها: ۲۱ سنجهٔ تازه در `docs/selftest_docs.mjs` (مجموع ۱۶۶) و ۲۱ سنجهٔ تازه در
`tests/e2e_app.mjs` (مجموع ۲۴۱) — ساخت صحنه، تزئین کارت، تب‌ها، لایهٔ فرود و
لندینگ‌های کوتاه، همه بدون خطا در jsdom.

`scrollWidth == innerWidth` در هر دو (بدون اسکرول افقی)، هدر بعد از اسکرول در `top:0`
می‌ماند، گوشی تیلت سه‌بعدی دارد و در حالت `prefers-reduced-motion` همه‌چیز ثابت و
خوانا می‌ماند.

| دعوت دوستان | با استارت شدن لینک، ربات دعوت را ثبت می‌کند؛ ۳ دعوت = ۷ روز پرو (یک‌بار) |
| نمایش پرو در مینی‌اپ | ربات فایل `docs/pro_users.json` را می‌نویسد (کلید = `sha256("tg-pro:"+آیدی)[:16]`)؛ مینی‌اپ همان فایل را می‌خواند |

دستورات مرتبط در ربات: `/buy` (یا `/pro`) · `/invite` · `/top` (جدول دعوت‌کننده‌ها) · `/status` · `/grantpro <id>` (مخصوص مؤسس).

> ⚠️ پوش این فایل از داخل GitHub Actions انجام می‌شود (`permissions: contents: write` + `PRO_STATUS_PUSH=1`). اگر آن را خاموش کنی، مینی‌اپ همه را «پایه» نشان می‌دهد.

## 🧠 نکات مهم

**۱) پیام‌های زمان وقفه گم نمی‌شوند**
`bot.py` با `offset = 0` شروع می‌کند؛ تلگرام همه آپدیت‌های تأییدنشده را دوباره می‌فرستد. کاربر پیام می‌دهد، ۶۰ ثانیه بعد جواب می‌گیرد.

**۲) دو ربات همزمان نمی‌شوند**
`concurrency` تضمین می‌کند فقط یک جاب پول کند. دو نمونه همزمان = خطای `409 Conflict` در تلگرام.

**۳) اگر ریپو ۶۰ روز بی‌فعالیت بماند**
GitHub زمان‌بندی را خاموش می‌کند. `keepalive.yml` اول هر ماه یک کامیت خالی می‌زند.

**۴) توقف**
**Actions → TradeGuard Bot → ••• → Disable workflow**

**۵) محدودیت صادقانه**
اجرای سرویس دائمی روی Actions یک **منطقه خاکستری در قوانین گیتهاب** است. برای تست، دمو، و شروع کاملاً کار می‌کند. برای **فروش واقعی با مشتری پول‌دهنده**، یک VPS ۵ دلاری (با پرداخت تتر، بدون KYC) حرفه‌ای‌تر و بدون ریسک است — راهنما در `HOSTING_NO_SLEEP_FA.md`.
